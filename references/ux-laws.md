# UX laws

Short, practical versions of the behavioural laws most useful in interface design. Each line says what the law means and what to do about it.

| Law | What it says | Do this |
|---|---|---|
| Hick's law | Decision time grows with the number of choices shown at once. | Cut or group options at decision points; highlight a recommended choice; reveal advanced options later. |
| Miller's law | Working memory holds only a few items, about four chunks. | Group fields, menu items and steps into small sets; never make people carry information between screens. |
| Fitts's law | Time to hit a target depends on its size and distance. | Make frequent and primary actions large and near; keep destructive actions small and apart; use screen edges and corners on desktop. |
| Jakob's law | People expect your product to work like the others they use. | Use familiar patterns for common tasks; innovate only where it clearly helps, and test it. |
| Doherty threshold | Responses under about 400 ms keep people in flow. | Set a performance budget; respond instantly to input even if work continues; see `states-and-errors` for waits. |
| Tesler's law | Every task has complexity that someone must carry. | Move complexity from the user to the system where possible (defaults, automation), without hiding what people need to know. |
| Peak-end rule | People judge an experience by its most intense moment and its end. | Design the peak and the ending deliberately: completion, confirmation, and how cancelling feels. |
| Serial position effect | First and last items are remembered best. | Put key items at the start and end of lists and navigation. |
| Zeigarnik effect | Unfinished tasks stay on people's minds. | Show progress, save drafts, and make it easy to return; never use it to nag. |
